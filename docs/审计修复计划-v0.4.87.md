## 修复方案

### B4：`mihomo/mihomo.go` writeConfig
- delete 清单追加 `delete(cfg, "listeners")`
- 测试：带 `listeners: [{listen: 0.0.0.0}]` 的 YAML 重写后配置无 listeners 键

### F4：`agent/poc_scaffold.go` cmdi 模板
- `r"uid=\\d+\\("` → `r"uid=\d+\("`（反引号原样透传）
- 测试：生成脚本含正确正则、不含 `\\d`

### F3：`agent/tools_jobs.go` jobStart
- `jobLifecycleMu.RLock()` 升级为 `Lock()`：同名「读旧→杀旧→启动→登记」全程互斥
- 测试：两 goroutine 并发同名 job_start → 仅 1 个存活进程、1 份 meta、清理可杀

### B2：`server/auth.go` + `cmd/pojun/main.go`
- 新增 `ensureSetupToken(dataDir)`：密码未初始化时确保 `<dataDir>/setup-token`（0600）
- `authInit` 要求 `X-Setup-Token` 匹配；成功后删除文件；已设置密码时维持 403
- 测试：无 token 拒绝 / 带 token 成功且文件删除 / 已设置后 403

### B3：`server/server.go`
- 新增 `limitBody(32<<20)` 中间件（`requireAuth` 外层），豁免
  `POST /api/workspace/upload`（512MB）与 `POST /api/chat/upload`（128MB）
- 测试：40MB JSON → 413；豁免路径不受影响

### F2：`db/tasks.go` + `db/task_archives_restore.go`
- DeleteTaskCascadePrepared 事务追加 DELETE：intercept_pending（task_id::text）、
  task_progress、credential_access_log、credentials
- CompleteTaskArchive 追加：task_progress / credentials / credential_access_log
- 测试：硬删除与归档后四表为空

### F1：`agent/tools_auth.go` + `agent/tools_http.go`
- parseAuthEntries 去排序、无效条目占位（与 DB 数组等长同序）
- session_login：全空占位条目报「auth_index=N 不是有效凭据条目」并列出有效索引
- auth_request：未传索引时选第一条有效凭据
- 工具描述同步：auth_index 对应资产 auth 数组原始顺序
